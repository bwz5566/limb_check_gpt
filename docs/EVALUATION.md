# 数据集与效果评测

## 三类验证必须分开

1. **软件验证**：接口、保存、状态机、文件读取和公式是否正确。可使用模拟输入。
2. **模型能力验证**：固定真实样本与人工真值对照，计算覆盖率、误报漏报。
3. **使用场景验证**：真实设备、环境、动作配合和流程时长。需要目标用户参与。

本项目交付软件测试和评测工具，不附带真实样本准确率。MediaPipe 公开关键点评测数字不能当作本项目的缺指检出率。

## 标签定义

所有“阳性”指当前检查项有疑点/目标存在，不是人员不合格。

| 检查项 | flag 标签应表示 |
| --- | --- |
| limbs | 人工有依据确认的可见肢体结构疑点；与姿态/透视问题分开记录 |
| fingers | 经确认的可见手指缺失/短缩；不要用弯曲或胶带遮挡替代 |
| nails | 可见甲油、甲片等目标存在 |
| tattoo | 可见纹身，且当前样本确有该部位可见 |
| scar | 人工确认的疤痕；无法与其他皮肤标记区分时用 uncertain |
| hair | 按事先定义的标准标注疑似染发；不可仅凭不确定颜色强行分类 |

clear：人工能够观察并确认没有目标；uncertain：人工也无法确定；not_assessed：不适用或没有观察。未标注保留空白。

## 建立验证集

- 先固定每个标签的定义、标注依据和检查范围。
- 收集经授权的正常、真实目标、遮挡、弯曲、逆光、弱光、背景干扰、不同设备样本。
- 真实缺失样本与模拟遮挡样本分数据集统计。无真实缺失样本时只能报告遮挡测试结果。
- 使用匿名受试者 ID，同一人的数据不跨训练/调参集与最终验证集。
- 建议双人独立标注有歧义样本，分歧由第三方或业务专家复核；记录备注。
- 每次模型、提示词或阈值变化使用固定版本验证集。不要只挑表现好的样本。

样本规模和验收门槛由实际用途及误差成本确定。小样本指标不代表总体准确率；对重要指标还应给置信区间，当前界面未实现区间估计。

## 指标公式

仅人工标签为 clear/flag 的样本进入有效分母。系统 uncertain/not_assessed 算弃判，不被当作正确，也不会直接混进二分类矩阵。

- TP：真实 flag，预测 flag。
- TN：真实 clear，预测 clear。
- FP：真实 clear，预测 flag。
- FN：真实 flag，预测 clear。
- 可判断覆盖率 = `(TP+TN+FP+FN) / 有确定真值的全部样本`。
- 条件准确率 = `(TP+TN) / (TP+TN+FP+FN)`。
- 条件召回率 = `TP / (TP+FN)`。
- 条件误报率 = `FP / (FP+TN)`。
- **全阳性检出率** = `TP / 所有人工 flag 样本`，包括系统无法判断的阳性样本。

必须同时看覆盖率与全阳性检出率，避免一个大量拒绝判断的模型显示很高的条件准确率。分母为零返回 null，UI 显示 —，不返回 0% 或 100%。

报告级评测：图片一份、视频一份、摄像头会话一份；不是每帧一个样本。视频任一评估帧触发疑点时报告 flag。模拟记录（source=synthetic 或 synthetic=true）排除。无人工标签的记录列入 unlabelled，不进入准确率。

重复分析同一输入会产生不同 run_id，每个记录都计数；评测集应控制每个样本每个版本的次数。版本不同的记录混在一起时 UI 会警告；按 engine/rule_version/dataset 过滤比较。

## 操作流程

1. 导入样本，查看实际取到的帧和时间点。
2. 保存报告并添加人工标签、数据集、匿名受试者 ID。
3. 在效果评测中筛选 `validation-v1` 和具体版本。
4. 导出 CSV 用于逐项检查误报/漏报，导出 JSONL 留存清单。
5. 离线运行：

```bash
python3 scripts/evaluate.py --dataset validation-v1 --rule-version rules-1.0.0 --output output/evaluation.json
python3 scripts/evaluate.py --manifest output/manifest.jsonl --dataset validation-v1
```

完整证据和帧指标在单份 JSON 或 SQLite 备份中，清单导出不包含图片。

## 效果报告至少包含

数据集来源与授权、受试者人数/样本数、每项阳性阴性数量、模型/规则/提示词版本、设备与拍摄条件、覆盖率、条件准确率/召回/误报率、全阳性检出率、失败样例、平均及分位延迟、限制与未覆盖场景。

当前工具记录单帧平均时延和每步耗时；正式容量测试中的并发、p50/p95、服务端资源占用需另外开展。没有服务器模型或并发服务时不虚构这些指标。
